# BUG-002: a API aceita mais de 5 unidades por produto

| Campo | Valor |
|---|---|
| ID | BUG-002 |
| Severidade | Média |
| Prioridade | P2 |
| Ambiente | https://verzel-store.qa-test-verzel-store.workers.dev, v2.3.0, Postman, 2026-10-06 |
| Cenário relacionado | CT-17 |
| Critério violado | CA10 |
| Camada afetada | API (`/api/carrinho/calcular` e `/api/pedidos`). A UI limita corretamente em 5. |

## Pré-condições

Nenhuma.

## Passos para reproduzir

No Postman, use o método, a URL e o corpo JSON abaixo (Raw JSON, `Content-Type: application/json`). Os comandos `curl` são o equivalente para o terminal.

```bash
curl -s -X POST https://verzel-store.qa-test-verzel-store.workers.dev/api/carrinho/calcular \
  -H 'Content-Type: application/json' \
  -d '{"itens":[{"produtoId":"P001","quantidade":6}]}'

curl -s -X POST https://verzel-store.qa-test-verzel-store.workers.dev/api/pedidos \
  -H 'Content-Type: application/json' \
  -d '{"cliente":{"nome":"Maria Silva","email":"maria@exemplo.com","cep":"01310-100"},"itens":[{"produtoId":"P001","quantidade":6}]}'
```

## Resultado atual

- `/api/carrinho/calcular` responde **200** com `quantidade: 6` e total R$ 359,40.
- `/api/pedidos` responde **201** e gera o número `VZ-737777`, com 6 unidades.
- Também aceita quantidades absurdas, como 1.000.000 (total R$ 59.900.000,00), em `calcular`.
- Quantidades 0, 1.5, -1 e texto são rejeitadas corretamente (422 `QUANTIDADE_INVALIDA`).

## Resultado esperado

Trecho da documentação (CA10): "Cada produto pode ter no máximo 5 unidades por pedido. A regra vale para a interface e para a API."
Tabela de erros: "422 QUANTIDADE_MAXIMA_EXCEDIDA: A quantidade de um produto é maior que 5."

Resposta 422 com `erro.codigo` igual a `QUANTIDADE_MAXIMA_EXCEDIDA` e `campo` apontando para `itens[0].quantidade`.

## Impacto

A regra pode ser contornada chamando a API diretamente. Qualquer cliente da API (por exemplo outro front) cria pedidos acima do limite.
